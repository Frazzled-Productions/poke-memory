# Plan: #2022 Leftovers from the auto-* removal: two dead autofix workflows, four orphaned scripts, a stale workflow-expert map

## What this is

#2003 / #2004 removed fourteen Claude-driven workflows on 2026-08-16 and dated the docs honestly rather than rewriting them. Three leftovers were missed. This change deletes the code that can no longer fire, deletes the helper scripts that genuinely have no caller, and re-grounds `.claude/agents/workflow-expert.md` in the workflows that still exist.

One correction to the issue, verified in the working copy: **only two of the four named scripts are orphaned, not four.** `.github/scripts/check-issue-staleness.sh` and its `.test.sh` are live, called by `.claude/agents/planner.md:35` (the #1322 pre-flight staleness check) and `.claude/commands/batch-issues.md:85` (step 6 of the batch pre-flight). Both are current, human-triggered paths that AGENTS.md still points at. Deleting them would break `/batch-issues` at step 6. This plan keeps them and deletes only the `extract-linked-issues.sh` pair.

The change is delete-and-correct only. No behaviour is added, and no replacement process is invented: WORKFLOW.md's dated-banner precedent (`WORKFLOW.md:3-25`) exists because inventing one before it is decided is worse than an honest gap.

## Approach

**The autofix pair: delete rather than re-point.** The alternative was to retarget the branch-prefix gates at whatever branch names the Mac-local loop (`Frazzled-Productions/frazzled-loop`) produces. Rejected: retargeting the gate is the easy half, and the hard half is that nothing consumes a `/fix` comment any more, so a retargeted workflow would still post into a void. Re-creating either file later is a `git show` away, and the PR body should carry the deleting commit SHA so that is a one-step recovery.

**workflow-expert.md: rewrite the affected sections, do not banner them.** WORKFLOW.md earned its banner because it is partly a historical record of how work flowed. `workflow-expert.md` is not a record; it is a knowledge base loaded to answer questions about the workflows in front of it, and a banner would leave the wrong answers in context to be reasoned from. The surviving facts are enumerable from the YAML, so a rewrite invents nothing. Section by section:

- Front matter `description` (`:3`) and the "Why you exist" paragraph (`:12`): drop "cycle caps" and the salvage flow from the advertised expertise; keep idempotency markers, fork-PR guard, permissions and the three incidents (#1859 / #1815 / #1806), which were CI and preview-gate failures and are untouched by the auto-* removal.
- Idempotency-marker table (`:25-34`): every row except `<!-- vercel-autofix -->` is written by a deleted workflow, and that row goes with its file. Replace the body with the markers that exist today, all verified by grep over `.github/workflows/`: `<!-- coverage-report -->` (`coverage.yml:94,148`), `<!-- qa-drift-check -->` (`auto-release.yml:254`), `<!-- cron-health-monitor:<file> -->` (`cron-health-monitor.yml:242`), `<!-- monitor:grade-log-divergence -->` (`monitor-grade-log-divergence.yml:115`), `<!-- pokeapi-species-monitor -->` (`pokeapi-species-monitor.yml:93`), `<!-- pr-check-monitor:<sha> -->` (`pr-check-monitor.yml:90`), `<!-- stale-preview-check -->` (`stale-preview-check.yml:114,153`), and `<!-- vercel-preview-fired:<sha> -->` (`vercel-preview-on-ready.yml:246`, flagged as belonging to a disabled workflow).
- Salvage pattern (`:36-45`) and cycle cap (`:47-49`): delete outright. Both describe `auto-issue.yml` / `auto-pr.yml` mechanics with no successor to describe.
- Fork-PR guard (`:51-59`): keep the rule, which is the security-relevant part, and re-anchor the example on a surviving user. `coverage.yml:30`, `changelog-gate.yml:35`, `migration-check.yml:22` and `qa-issue-label.yml:43` all carry the same guard and all cite `auto-review.yml` in their comments as the pattern source, so pick one and state the pattern directly rather than by reference.
- Gotchas (`:61-69`): the `if: always()`, concurrency and permissions bullets stand. Re-anchor the `labeled`-filter bullet on `version-bump-gate.yml` / `main-pr-source-gate.yml` / `changelog-gate.yml`, which all take `labeled`/`unlabeled` and filter by label name in the step. Re-anchor the author-association bullet on the one surviving command, `/preview` in `vercel-preview-on-ready.yml`, noting that workflow is disabled. Re-anchor the `workflow_dispatch`-only example on `visual-baseline-update.yml` or `qa-preview-deploy.yml`, both dispatch-only and both live; `issue-overlap-scan.yml` is gone.
- Project-board transitions (`:71-80`): reduce to the single surviving row, `auto-status.yml` on issue close, and say plainly that no other transition is automated any more, so a reader does not go looking for the machinery.

**Stale prose in surviving workflows is out of scope.** `changelog-gate.yml:34`, `coverage.yml:30`, `migration-check.yml:22`, `qa-issue-label.yml:43` and `cut-release.yml:33` each name `auto-review.yml` in a code comment as "same guard as". They are inert cross-references in files that work correctly, and sweeping them would widen the diff into five more workflow files for no behavioural gain. The `cut-release.yml:33` one is the only mildly misleading case (it asserts auto-review's skip "still applies"); note it in the PR body rather than fixing it here.

**AGENTS.md is untouched.** The mandatory workflow-expert review on every `.github/workflows/**` change stays as written: its stated rationale is YAML's silent-failure mode, not the auto-* pipeline, so the removal does not weaken it. That rule applies to this change too (see Testing).

## Risks and unknowns

- **The wasted runs continue until `main`.** GitHub resolves `workflow_run` and `deployment_status` workflow definitions from the default branch, so deleting the files on `qa` does not stop `Auto-fix CI failures` from starting and skipping a run per CI completion. It stops at the `qa -> main` promotion. Worth saying in the PR body so nobody reads a post-merge run as a failed deletion.
- **Unverified from this lane:** that neither autofix check is a required status check, and that `vercel-preview-on-ready.yml` is still `disabled_manually`. Both come from WORKFLOW.md (`:193`, `:740`), not from the GitHub API, because this lane had no network. Check both before merging (Testing step 5).
- **Knowledge deleted from workflow-expert.md is recoverable but not obvious.** The salvage and cycle-cap sections are the only concise write-up of those mechanics outside the deleted YAML. They survive in git history and in WORKFLOW.md's historical sections, but if the Mac-local loop rebuilds a similar pipeline, whoever does it should be pointed at `WORKFLOW.md:448-460` and the deleting commit rather than expected to rediscover it.
- **The issue's line numbers were accurate.** Every citation in #2022 matched the working copy at `d7181d15`, including `ci-failure-autofix.yml:21` and `vercel-failure-autofix.yml:23`. The only factual error was the script count, corrected above.
- **A fourth leftover exists and is worse than these three** (see Open question 1). It is a live blocker, not a cosmetic one, so it should not be lost inside this cleanup.
