# Plan: #2013 /batch-issues pre-flight blocks on disabling the deleted Auto Review workflow

## What this is

#2003 / #2004 deleted the fourteen Claude-driven Actions workflows on 2026-08-16, `auto-review.yml`
among them, but did not touch `.claude/**`. Two files there still treat that automation as live:

- `.claude/commands/batch-issues.md` makes `gh workflow disable "Auto Review"` a **blocking**
  pre-flight step, and its own instruction on failure is to stop and escalate to the maintainer.
  The command can no longer succeed (`could not find any workflows named Auto Review`), so the next
  `/batch-issues` drain halts before dispatching a single implementer. `/ship` defers to
  batch-issues for its gate rules, so it inherits the block.
- `.claude/agents/workflow-expert.md` documents removed workflows as current. It is the mandatory
  reviewer for every `.github/workflows/**` change, so a reviewer working from a stale map is the
  live risk.

This is a documentation-and-process correction, not a code change. No product behaviour changes.

I re-verified the issue's claims against this worktree at `7bbd0ed0` (the issue read `81deaebf`).
Every line number it cites is still accurate. I found four further sites it does not list, called
out below.

## Approach

Three decisions worth stating.

**Trim by re-anchoring, not by deleting.** The naive reading of "trim to the workflows that still
exist" deletes any paragraph naming a removed file. That would throw away four pieces of still-valid
GitHub Actions knowledge whose only fault is a dead example: the fork-PR guard, trigger-event
filtering, author-association gating, and `workflow_dispatch` blast radius. Every one of those rules
has a live anchor elsewhere in `.github/workflows/`. Rule: delete a section when the *mechanism* is
gone (cycle cap, salvage post-steps, board transitions); re-anchor when only the *example* is gone.

**Two marker rows survive their producers and must be kept, re-labelled.** This is the part a
mechanical trim gets wrong.

- `<!-- auto-status -->` still has a producer: the local hook `.claude/hooks/mirror-todos-to-comment.sh:37`
  writes it. Only the workflow that used to PATCH it is gone.
- `<!-- auto-review:N -->` and `<!-- auto-review-sha:<sha> -->` have no producer but a live
  **consumer**: `vercel-preview-on-ready.yml:56` and `:181-210` gate the Vercel deploy hook on a
  bot-authored comment carrying that marker plus `Verdict: Looks good to me`. Delete those rows and
  the next person to touch that workflow has no explanation for what it is looking for.

Rejected: deleting all five `auto-*` marker rows in one pass. It reads tidier and is wrong twice.

**Renumber rather than leave gaps.** `batch-issues.md` numbers its pre-flight, wrap-up and
graceful-exit steps and cross-references them by number in six places. Leaving "step 2 (removed)"
placeholders would be less error-prone but litters an instruction file that agents read literally.
Renumber, then verify by grepping for every `step N` reference and re-reading each in context.

Rejected alternative for the whole issue: keeping pre-flight step 2 as a no-op with a "harmless if it
fails" caveat. That contradicts the file's own escalation instruction, and leaves the false rationale
("the in-session reviewer is redundant with Auto Review") in place, which is now inverted: the
in-session `code-reviewer` is the *only* review. Making that explicit is the substantive part of this
change, not the deletion.

## Testing

There are no unit tests over `.claude/**` (confirmed: nothing under `scripts/`, `.github/scripts/` or
the vitest projects asserts on these files), so verification is command-level and manual.

1. **The acceptance test: dry-run the edited pre-flight.** Run the surviving pre-flight steps of
   `batch-issues.md` verbatim as written - the `gh issue list` backlog query, the `git fetch` +
   `git rev-list --left-right --count origin/main...origin/qa` sync, the `gh pr list` open-PR check,
   `.github/scripts/check-issue-staleness.sh` on one open issue, and the two `gh run list` noise
   queries. Every one must exit 0. This is what #2013 actually asks for: the drain no longer runs a
   command that cannot succeed.
2. **No live reference to a deleted workflow.** After the edit,
   `grep -rn "Auto Review\|auto-review\|auto-issue\|auto-pr\|auto-retro\|overlap-scan\|auto-plan\|auto-split" .claude/`
   must return only the deliberately-kept, deliberately-labelled `auto-review` marker rows in
   `workflow-expert.md`. Any other hit is a miss.
3. **Every named workflow resolves.** For each `<name>.yml` mentioned in the edited files, assert the
   file exists under `.github/workflows/`. One-liner:
   `grep -ho '[a-z0-9-]*\.yml' .claude/agents/workflow-expert.md .claude/commands/batch-issues.md | sort -u`
   then check each against `ls .github/workflows/`.
4. **Step-numbering integrity.** `grep -n "step [0-9]\|steps [0-9]" .claude/commands/batch-issues.md`
   and read each hit in context. Confirm the pre-flight runs 1-7 with no gap, wrap-up 1-7, the
   graceful-exit guardrail 1-3, and that `# 6a.` / `# 6b.` now sit under step 6.
5. **`npm run lint`.** Covers `lint:em-dash`, `lint:i18n`, `lint:pseudo-locale`, `lint:changelog` and
   `lint:agents-size`. Note two things: the em-dash detector treats developer docs as out of scope,
   so British-English and no-em-dash compliance in `.claude/**` is on the author, not the linter; and
   `lint:agents-size` measures `AGENTS.md` only, which this change does not touch.
6. **`npm run pre-pr`.** House rule regardless of diff shape. The diff is markdown-only, so
   `build` / `test` / coverage are unaffected and `test:diff-coverage` sees zero changed product
   lines. `changelog-gate.yml` only fires on `app/**`, `components/**`, `lib/**`, so no changelog
   fragment is required (internal-only change).
7. **Review passes.** `code-reviewer` on `git diff origin/qa...HEAD`, plus `workflow-expert` per the
   AGENTS.md ownership table for a non-trivial `.claude/agents/**` change. Note the oddity that
   `workflow-expert` is reviewing edits to its own definition; it is read-only and advisory, so this
   is fine, but brief it explicitly on that.

## Risks and unknowns

- **Renumbering is the real defect surface.** Six cross-references in `batch-issues.md` break if the
  renumber is done carelessly, and a wrong "return to step 2" sends a future drain to the wrong
  wrap-up step. Test 4 exists for this.
- **Line numbers drift.** The anchors above are verified at `7bbd0ed0`. If anything lands on these
  two files first, relocate by heading text rather than by line number.
- **A live gate is already broken, and this change does not fix it.**
  `vercel-preview-on-ready.yml` requires a bot-authored auto-review LGTM at the current HEAD SHA
  before firing the Vercel deploy hook. No such comment can exist since #2004, and
  `vercel.json` disables git-driven preview deploys, so **PR preview deploys now only fire via a
  manual `/preview` comment**. This is a consequence of the same cleanup, it is outside `.claude/**`,
  and it is not in #2013's scope. See open question 1.
- **`ci-failure-autofix.yml` and `vercel-failure-autofix.yml` post `/fix` comments** that nothing
  handles any more (`auto-pr.yml` is gone). Both files' header comments say so explicitly. Same
  cause, also outside this issue's scope; worth a follow-up issue alongside the preview gate.
- **Nothing stops this recurring.** The gap between `.github/workflows/**` and the prose that
  describes it is enforced by nobody. See open question 3.
- **Low unknown:** whether `/preview` and the `<!-- vercel-preview-fired:<sha> -->` idempotency
  marker should join the `workflow-expert` marker table. They are live and undocumented there. Folded
  into open question 2.

## Open questions for Fraser

**1. The orphaned preview-deploy gate.** `vercel-preview-on-ready.yml` can no longer satisfy its
auto-review condition, so PR previews only fire on a manual `/preview`.

- (a) File it as a separate issue and keep this PR docs-only.
- (b) Fix it in this change: drop the review leg so the gate is CI-green plus fork guard.
- (c) Leave it: `/preview` on demand is acceptable.

**Recommendation: (a).** It is a `.github/workflows/**` change, which per AGENTS.md needs its own
`workflow-expert` review and carries YAML's silent-failure risk. Bundling it into a docs cleanup
mixes two risk profiles in one PR. It is also arguably a WHAT question in itself: (b) restores
automatic previews on every green PR, which may be more deploys than you want.

**2. Trim only, or trim and complete, the `workflow-expert` marker table?**

- (a) Literal ask: delete the dead rows, re-attribute the two that survive, stop.
- (b) Also add the live markers the table has never documented:
  `<!-- ci-autofix:<run-id> -->`, `<!-- pr-check-monitor:<sha> -->`,
  `<!-- cron-health-monitor:<file> -->`, `<!-- vercel-preview-fired:<sha> -->`.

**Recommendation: (b), bounded to exactly those four.** The agent's entire job is reviewing
`.github/workflows/**`, and an incomplete marker table is the same failure class as a stale one. The
cost is four table rows and the four greps I have already run. Trade-off: it widens the diff slightly
beyond what #2013 asks for.

**3. Add a forcing function so this cannot recur?** The repo's own retro discipline prefers an
enforceable invariant over a doc fix. The natural one is a lint that fails when `.claude/**` names a
`.github/workflows/*.yml` that does not exist on disk.

- (a) Follow-up issue, not this PR.
- (b) Build it here, wired into the `lint` chain.

**Recommendation: (a).** It needs a design decision I should not make unilaterally: `WORKFLOW.md`
*deliberately* names fourteen deleted workflows behind its "Partly historical" banner, so the rule
needs either an explicit exemption list or a scope limited to `.claude/**`, and getting that wrong
lands a lint that fails on `main` from day one. Worth doing, worth its own issue.
